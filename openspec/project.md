# 交互式汉字 —— 项目约束（Open Spec）

给 3-8 岁孩子的交互式汉字学习网页。本文件与 `specs/` 是产品行为的唯一事实来源：任何会话、任何 agent（包括 workflow 子 agent）改本仓库前先读这里；与三目的冲突的方案必须先向用户确认，不得静默降级。

## 三目的（最高约束，2026-11-14 与用户澄清）

1. **有趣认字**：让小朋友有趣地认识并记忆汉字。
2. **阅读闭环**：培养阅读兴趣，在只用已学字写成的故事里认识和复习学过的字。
3. **汉字网络**：把汉字连成系统网络，知其然知其所以然——部首归类、声旁家族、字源演变、组字拆字。

判定规则：一项改动必须至少服务一条目的；若以削弱另一条目的为代价（例如为扩量而牺牲网络性），属于范围变更，必须先经用户确认。

## 用户与使用方式

- 几个 3-8 岁的孩子，各自独立档案；孩子自己用平板玩，全程语音引导，操作极简，不要求识字。
- 家长偶尔介入（选字、备份），入口用算术门拦住孩子。

## 硬约束（非目标）

- 不做积分、排行、每日任务、限时——动力只来自内容本身。
- 纯静态部署（GitHub Pages），无后端、无 API 密钥、无用户追踪。仓库公开是「仓库默认私有」规则的用户批准例外。
- 进度只存浏览器本地（localStorage），家长端提供导出/导入备份兜底。
- 事实可靠性高于表现效果：不编造字源、不编造笔画说法，没有可靠依据就呈现朴素版本；面向孩子的台词里不出现英文字母和数字。

## 质量的定义

「做出来」= 验收场景可验证，不是文件存在：数据过程序化校验器（重做量产时随 change 引入）、交互行为有对应 e2e（playwright）、故事用字范围有程序化校验。

扩量（再批量生成内容）不得把质量重定义为「过校验器」而丢掉目的本身。2026-11-18 的 1000 字任务发生过一次此漂移：目的 2、3 静默出局，该批产物已于 2026-11-19 经用户决定整体撤回（见「实现状态对账」）。本 spec 体系即为防止复发而设。

## 实现状态对账（2026-11-19，量产撤回后）

主线当前只有 **4 个手绘定制课（日、月、木、人）+ 首页字卡/「会」印**。2026-11-18 批量产出的 996 个通用课、约 7000 个旁白音频及配套首页改造、家长选字器，经用户判定不符合质量要求，已于 2026-11-19 从主线和公开历史整体撤回（本地备份分支 `backup/1000-char`，指针 69b2b1d）；重做必须按「工作方式」立 change。

| 目的 | 状态 | 差距 |
|---|---|---|
| 1 有趣认字 | 起步：日月木人 4 个手绘定制课可学 | 第一版计划的明、林、森、休、青、清、晴 7 字尚未手绘；扩量到 1000 字需按 spec 重做 |
| 2 阅读闭环 | **未开始** | 故事生成、只用已学字校验、点字回课、故事朗读都没有 |
| 3 汉字网络 | 字源演变在 4 个定制课里有手绘演示（实物 → 甲骨文 → 楷书变形） | 1000 字拆字排序、部首/声旁分组、组字关系、网络视图没有 |
| 档案与备份 | 单一进度 + 「会」印 | 多孩子档案、导出导入、家长选字器（随撤回移除，按 progress-parent spec 重做）都没有 |

此表在 change 归档（`openspec archive`）时同步更新，保持与事实一致。

## 工作方式（Open Spec 流程）

- 改行为先立 change（`changes/<id>/`：proposal → tasks → spec 增量），实现完成并验证后 archive 合入 specs。
- specs 是约束性合同（含尚未实现的场景，如阅读闭环）；上面「实现状态对账」负责跟踪哪些已落地。
- 批量生成内容（workflow / subagent）的任务书必须引用对应 spec 的 Requirement，不得只给数据 schema；完成标准是验收场景通过，不是「文件已生成」。

## 技术约定

- vanilla HTML/JS/CSS，数据驱动（`data/chars/*.json`、`src/chars/<字>/` 定制课）。
- 包管理 pnpm；TTS 用 edge-tts（zh-CN-XiaoxiaoNeural）预生成；笔画数据源自 Make Me a Hanzi（Arphic 许可，保留 `data/chars/ARPHICPL.TXT`）。
- 量产设施（通用课引擎 `src/generic.js`、字表 `plan-1000.json`、校验器 `scripts/validate.mjs`、测量脚本等）不在当前主线，存于本地分支 `backup/1000-char`；重做时经 change 评审后引入。
- 教训记录见总部 `pitfalls/hanzi-data.md`（junda 首读音不可信、并行 agent 干扰 e2e 等）。

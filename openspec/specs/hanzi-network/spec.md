# 汉字网络（目的 3）

## Purpose

把汉字连成系统网络，知其然知其所以然：部首归类、声旁家族、字源演变、组字拆字。当前只在排序层面落地（见 `project.md` 对账表）；呈现层的场景是约束性合同。

## Requirements

### Requirement: 字族与比较编排（目标态，2026-11-19 用户新增）

字表的编排必须（MUST）让同类、有关联的字相邻教学，用「比较」做教学抓手：同一部件家族（如人形族：人、大、夫、天、从、比、北、众——二人为从、相背为北、三人为众）、同一部首（亻、氵、日……）、同一声旁家族（青 → 清、晴、请、情……）聚在同一阶段先后出现。家族线索目录以 `data/sources/char-families.md` 为准，发现新线索必须回写该文件。

#### Scenario: 家族聚簇

- WHEN 生成或调整学习顺序
- THEN 同一家族成员的间隔不超过一个阶段，且教学动线里有该家族的比较环节（旁白或画面点出异同）

#### Scenario: 形近但不同源

- WHEN 两个字楷书形近但字源无关（如「朋」并不是两个月亮）
- THEN 比较教学只讲形态关系，或明说「长得像、其实不是」，不得讲成字源

### Requirement: 学习顺序体现结构

字表 = 字频选 1000 个生活常用字 + 拆字依赖排序：每个合体字必须（MUST）排在它全部部件之后，整体分阶段（字表数据文件随重做的 change 落盘）。日月木人 4 个定制课打头。

#### Scenario: 字表更新时自检

- WHEN 生成或更新字表顺序
- THEN 脚本断言每个合体字的全部部件的序号都小于本字序号，违例即失败

### Requirement: 组字拆字关系可见

- 定制课示范基准：日 + 月 → 明（天空亮起）、木 → 林 → 森、人靠木 → 休、青加氵/日 → 清/晴。
- 通用课层面：讲到合体字、且其部件刚在前面学过、构成关系有把握时，旁白必须（MUST）至少点出一层构成关系（「X 里有刚学过的 Y」）；拿不准就不提，不硬编。

#### Scenario: 有把握时点出构成

- WHEN 通用课的字的某部件在近几个阶段内刚学过，且构成关系明确
- THEN 该字的旁白台词中有一句点出这个构成关系

#### Scenario: 拿不准时保持朴素

- WHEN 构成关系或字源没有可靠依据
- THEN 台词不提构成和字源，只做朴素描述（宁可少说，不可说错）

### Requirement: 部首归类与声旁家族（目标态）

家长端的全字表必须（MUST）支持按部首、按声旁分组浏览；点一个部件或声旁，能看到它参与构成的那些字，以及这些字分别在第几阶段学。

#### Scenario: 按声旁浏览

- WHEN 家长在字表中选「青」的声旁家族
- THEN 看到 清、晴、请、情 等字 grouped 在一起，标注各自学习阶段

### Requirement: 字源演变（目标态）

字源动画（实物 → 甲骨文 → 楷书）必须（MUST）只在有可靠来源时呈现：字形对照真实古文字字形（以权威字书/拓片收录为准，如汉典、国学大师所录甲骨文），文字解释以《说文解字》为第一依据；说文未收的后起字（如「晴」）只讲形声结构，不虚构字源。无来源就不呈现该层，禁止凭印象画形、凭通识编说。

#### Scenario: 无来源的字

- WHEN 某字找不到可靠古文字形来源
- THEN 该字的课不出现字源演变环节，直接走通用动线

#### Scenario: 字形与依据不符

- WHEN 画的甲骨文/小篆字形与所依据的拓片、字书形态不一致（例：「人」画成深弯腰躬身，而甲骨文是侧立人形）
- THEN 判为缺陷，返工到一致；台词里的字源演绎一并修正

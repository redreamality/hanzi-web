# 造字 SOP：审美与溯源（2026-11-19）

本 SOP 由 add-remaining-first-batch 一线的失败与返修原因提炼，每条红线都有实战出处。**所有后续造字任务（含 1000 字 workflow、返修、通用课）的任务书必须引用本文件 + 对应 spec Requirement + 该字的 etymology 考据行**；违反红线的交付不进验收。

## 1. 溯源解读（考据）SOP

1. **依据层级**：《说文解字》原文 > 汉典「说文小篆」拓片（`swxz/<大写码位>.svg`）> 汉典字源区字形（`zy/jiaguwen`、`zy/xiaozhuan`）> 通识印象（最后，慎用）。
2. **动工前先填 `changes/<id>/etymology.md` 的该字行**（说文原文 / 字形依据 / 画法 / 讲法 / 状态），画完回写。已有第一版 11 字的表在归档 change 里，后续字表延续同格式。
3. **两形并存**（森的横排 vs 品字、明的从日 vs 从囧）：默认取说文一系；教学动线强烈需要另一形时，记录取舍理由并标「待用户定夺」。
4. **台词红线**：
   - 字源只讲有据内容；说文未收的后起字（如晴）只讲形声结构，不得虚构字源；
   - 视觉描述用「像」明喻（「像一节小竹子」），不作字源断言；
   - **禁止演绎**——「人」是侧立直立人形，不得加「弯腰」戏（初版 ren 的教训）；
   - 形近不同源（朋≠二个月）只讲形态关系，或明说「长得像、其实不是」。
5. **字形核对方法**：参考 SVG 栅格化成剪影/密度图 → 与渲染轮廓逐结构比对（三叉数、横数、框形开口、部件比例）。工具坑见总部 `pitfalls/hanzi-data.md`（zdic 大写码位、防盗链 Referer、file:// 栅格化三连坑）。
6. **拿不准宁可不画**：forms 可以只有小篆+楷书、甚至组字+楷书（青不画甲骨文、清晴不画古文字的先例）。

## 3. 验收协议

1. **每字**：`lessonTests` + ≥2 条本字特有测试；独立端口（41xx）；过滤一律 `pnpm exec playwright test <file>`（**禁** `pnpm test:e2e -- <file>`，会跑全量）；**两遍全绿**。
2. **自检**：像素采样（关键色值、边界带亮度、残留扫描）或 DOM 几何断言，给数字不给形容词。视觉分析服务只作**抽样加分项**（有长故障窗，见 pitfalls），不作门禁；最终画面以用户终审为准。
3. **汇报必须明说拿不准的点**；主会话独立复跑 + 有权打回返工单。
4. **满载时序 flake**：先原样重跑再当 bug 查；change 级门禁 = 空载全量两遍全绿，且 **passed 数必须与 `--list` 总数对账**。
5. **引擎问题上报不越权**：字课 agent 发现引擎缺陷（如清上报的短笔画倒写盲区）→ 报主会话修 → 全字受益；不私自改共享文件。

## 4. 批量（workflow）编排约束——给 1000 字用

1. 任务书必须引用：spec Requirement + 本 SOP + 该字 etymology 行 + 所属字族（`data/sources/char-families.md`）。
2. 排序按**家族聚簇**（spec 场景「家族聚簇」：同族间隔 ≤1 阶段）；同族字共用视觉母题与色系。
3. **每批 ≤8 字**（25-agent 满载会把时序敏感 e2e 跑花），批内配**独立审校 agent**：带「上一手不够好」的怀疑复核考据行、台词、画面像素，直接改完复验。
4. **通用课也必须包含**（目的 3 不许静默出局的操作化）：构成关系台词（部件刚学过且有把握时）、声旁点题（形声字）、说文一行字理（有据时）。
5. 完成标准 = 验收场景通过，不是文件生成（`openspec/project.md`「质量的定义」）。
6. **先样板后放量**：每类新课程形态先做一个样板字过用户终审，批准后再批量（第一版「先惊艳后扩量」的教训，反过来就是 1000 字任务的教训）。
